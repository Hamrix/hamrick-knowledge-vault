# Schema Drift and Referential Integrity

The live Hamrick Knowledge Vault outranks bundled assumptions.

Before consequential writes verify the live system policy, Aetheling Project Index, Vault-First rules, Claims/People/Sources structure, confidence vocabulary, and relevant project-state files.

Check:
- claim/source/person wikilinks resolve;
- project-state links resolve;
- `last-reviewed` uses `YYYY-MM-DD`;
- native confidence values remain valid;
- GEDCOM is not used as canonical evidence unless explicitly requested;
- no high-confidence claim relies only on quarantined, unsourced, or AI-derived material.

If the live schema has changed, report the drift and adapt narrowly. Do not silently migrate the vault or create a parallel schema.
